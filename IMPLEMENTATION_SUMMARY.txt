┌─────────────────────────────────────────────────────────────────┐
│                     HOW IT WORKS                                │
└─────────────────────────────────────────────────────────────────┘

FLOW 1: Natural Language Query (with NLU)
───────────────────────────────────────────
User: "butter chicken from Inayat Cafe"
   ↓
Query Parser (NLU) detects intent
   ↓
Intent = "specific_item_specific_store"
Item = "butter chicken", Store = "Inayat Cafe"
   ↓
Search Service → Find store by name (fuzzy match)
   ↓
Search items in that store
   ↓
Return: Butter Chicken @ Inayat Cafe (269₹, 4.5⭐)


FLOW 2: LLM Structured Query (Pre-parsed)
──────────────────────────────────────────
LLM already understood the query, sends:
{
  "intent": "specific_item_specific_store",
  "item": "butter chicken",
  "store": "Inayat Cafe"
}
   ↓
POST /v2/search/items/structured
   ↓
Skip NLU, go directly to search
   ↓
Return results immediately
   ↓
Faster response, better control


FLOW 3: Vector/Semantic Search
───────────────────────────────
Query: "butter chicken"
   ↓
Generate embedding for query
   ↓
Search in OpenSearch using:
- item_vector (item embeddings)
- store_item_vector (item+store combined)
   ↓
Return semantically similar items
   ↓
Results: Items similar to "butter chicken"
         from various stores


FLOW 4: Fallback Chain
──────────────────────
User: "abc xyz"
   ↓
Try exact match → No results
   ↓
Try fuzzy match → No results
   ↓
Try semantic/vector search → Found!
   ↓
Return vector search results
   ↓
If still nothing, generic keyword search
